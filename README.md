# 今天也没倒闭 —— 硬核餐饮经营模拟器（第二阶段：多城扩张版）

纯前端单机文字策略经营游戏：React + TypeScript + Vite，IndexedDB 存档，Windows 浏览器本地可运行。

## 启动 / 构建 / 测试

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（默认 http://localhost:5173，浏览器打开即玩）
npm run build      # 类型检查 + 生产构建（输出 dist/，可本地静态服务器打开）
npm run preview    # 预览生产构建
npm test           # Vitest 自动化测试（14+1 项，覆盖需求十八全部条款）
npm run typecheck  # 仅类型检查
```

## 局域网（手机/其他电脑一起玩）

1. 一键（推荐）：命令行执行：
   ```bash
   npm run build
   node serve-lan.cjs        # 默认 8080 端口；换端口：set PORT=8888 && node serve-lan.cjs
   ```
   同一局域网设备浏览器打开 `http://<本机IP>:8080`（本机 IP 看脚本启动时打印的地址）。
2. 开发模式热更新：`npm run dev`（已配置 host 监听所有网卡），访问终端显示的 Network 地址（默认 5173）。

注意：
- 首次启动 Windows 防火墙会弹窗询问，请勾选“允许访问”（专用网络）；若仍不通，用管理员执行一次：
  `netsh advfirewall firewall add rule name="tnbr-lan" dir=in action=allow protocol=TCP localport=8080`
- 游戏为单机模拟，各设备的浏览器各自在 IndexedDB 里存档，互不同步。
- 验证服务是否正常：`node serve-lan.cjs --selftest`（应输出 SELFTEST OK）。

## 核心闭环

读当日天气与市场 → 采购（付现+入库，配送可隔日）→ 查库存保质期 → 定价/上下架/排班/营业时段 → 处理待办事件 → 确认营业计划 → 引擎模拟营业 → 每日损益+现金流 → 评价/口碑/事件/市场演化 → 自动存档 → 下一天。

## 规则要点

- 金额一律整数分、库存整数 g/ml/个：浮点误差被结构排除（测试14）。
- 采购=现金流出+库存资产；销售=按批次 FIFO 扣料计消耗成本；过期/储存损耗单独入账（测试1/2/4/8/13）。
- 缺关键食材不能出餐且不扣料（测试3）；熟练度影响出餐时间与品质（测试5）。
- 售价通过效用模型影响销量（测试6）；接待量受座位/服务员/厨房产线三重约束（测试7）。
- 凄惨身世每日固定 1000 元医疗费；豪门现金≤1万触发父母来电（5万~50万随机、14天冷却、累计记账）（测试9）。
- 采访 6 题按文档隐藏计分（≥10 客流增益 / <0 客流下滑），谎称年限累积可信度风险并有揭穿后续事件（测试10）。
- 粉丝 <1000 的探店博主只留评价、不产生持续客流加成（测试11）。
- IndexedDB 自动存档+3 手动槽位，刷新恢复完整状态，版本化含迁移钩子（测试12）。
- 同一天重复结算不重复记账（测试13）；现金为负有欠薪危机/贷款/变卖设备/家庭援助流程，连续 3 天现金为负破产结局。

## 第一阶段范围与后续

第一阶段（可玩核心闭环）实现：老板创建、长沙开店、市场采购（无起订金额门槛）、库存与保质期、菜单定价、员工熟练度与排班、客流与营业模拟（均匀到店+排队+缺料换点+限单拒客）、每日财务结算、随机事件、动态顾客评价（按厨艺/等待/价格/份量/卫生驱动）、自动存档、**营销系统**（短视频/传单/博主邀约/限时折扣/套餐促销/会员优惠/节日营销：三档预算、受众定向、成功率=内容质量×受众匹配×口碑×竞争、翻车风险、促销按折后真实收入记账不重复计账、结案输出投入→增量销售→增量毛利→客流变化→回头客留存的近似归因）；含 30 天自动运营与营销链路的回归测试由 `npm test` 持续验证。

本次增补（均在引擎内计算、带自动化测试）：
- **市场采购购物车**：食材行改为「加入购车」（同食材同供应商自动合行，低于起订量拒绝加入），顶部“食材市场/购物车”双 Tab，购物车页展示实时估价/运费/到货时间，支持逐行移除、清空与「一键购买」（结算失败的行保留在车内）；**购物车内容随游戏存档持久化，除非手动移除或购买成功**。
- **供应商规则**：仅保留 马王堆批发市场（最便宜、次日达、免运费）与 冻品供应链公司（稍贵、当日达、每单运费30元，全部食材均可供）；社区生鲜店与次日达团购已删除。
- **员工放假恢复**：当日完全未排班的员工按放假处理——疲劳 -50（`STAFF.fatigueRestNoShift`）、压力直接清零；有排班者维持每日小额恢复（疲劳-16、压力-4）。
- **按排班计薪**：员工工资按当日实际排班计算——早/午/晚/夜宵全部未排班的员工当日工资为 0（不上工、不积累经验和疲劳）；每日损益与总账的工资科目只计有排班者。员工页显示当日实发工资并对无排班者标注「当日无薪」，经营总览员工卡显示「今日应发工资」。
- **等待/弃单调优**：厨房队列改为“每条产线并行照看 2.5 道菜”（`CAPACITY.batchParallelBp`，炒锅+蒸柜+备台面并行），并整体上调各客群等待耐心；产能粗估同步引入并行系数，预警与限单口径一致。
- **菜品研究系统（新玩法）**：开局只解锁湘菜（祖传手艺，全部可售可上架）。其余菜系需先交学费学习——川菜5000 / 粤菜7000 / 快餐5000 / 甜品5000 / 饮品2000 / 西餐10000 / 日料20000 / 法餐50000 元；学习后逐道研究该菜系菜品：每次 200 元，界面提供菜名+风味线索，玩家从库存中选配料组合「开火试做」——配料种类完全对上且库存够一份样品即研发成功（消耗试做食材入账 cogs），该菜进入菜单定价可上架；配错则得到「令人困惑的实验菜」事件：倒掉，或送顾客试吃（50% 口碑+0.5+五星好评 / 50% 口碑-0.5+一星差评）。菜单页对未研究菜品显示 🔒需研究 并禁止上架。旧存档自动视为已全部学完解锁（不影响进行中的档）。
- **市井百态随机事件（均可重复出现）**：禹州水灾（旁观/捐助5000元口碑+5）；员工的心事（视而不见压力+10 / 真切关心——若关心，3天后触发后续“家庭的变故”：安慰则员工次日离职，资助3000元满意/忠诚+50）；捡到彩票（中奖50~10000元随机，兑奖入账或交给片警口碑+1）；员工想早退照顾病孩（同意：满意/忠诚+20口碑+1；拒绝：满意/忠诚-20）；邻桌骚扰事件（报警口碑+2 / 无视未来7天客流-20% / 挺身而出：50%口碑+5，50%口碑+8但医药费1500元）。
- **自定义配料用量**：菜品详情里每种配料可调 0%~200%（整数克重按基点折算，主料=配方第一项有标记）：成本、扣料、采购建议、自动购入、博主加量全部按调整后的实际用量计算；份量随之缩放——用料≥90%视为标准；缩料掉锅气（品质惩罚）、主料砍到60%以下重罚、被抓写差评的概率 = 缩水幅度 × (客群份量偏好 × 城市份量偏好)——长沙这类大份量亲民城市缩料高概率挨骂（"份量敷衍"1~2星），上海/巴黎等精品城市宽容甚至小幅加分；加料小幅提升品质但成本上升。菜单列表显示「用料N%」角标，可一键恢复标准配方。
- **自动购入（纯手动触发）**：库存速览勾选「只看在售菜品所需原料」后出现「设置自动购入」按钮：为每种在售所需原料设定目标库容（g/个）与时长（1~365天），选择供应商（马王堆次日达 / 冻品当日达+运费），保存并启用。旁边「自动购入」按钮点击后，凡可用库存低于目标库容的食材一键补购到目标值（受起订量、储存容量、现金约束；已满足的不动钱）。**不会在每日开局自动执行**；设置随存档持久化，过期/停用需重新设置，可随时停用（目标量保留）。
- **建议采购**：仅当可用库存低于「昨日消耗×1.2」时才出现建议量与「用建议量」按钮；不缺料不显示。
- **利润走势图**：经营总览新增纯 SVG 柱状+折线图，按日期显示最近 5 天净利润（绿正红负，折线连趋势点，无图表库依赖）。
- **当日建议购入**：菜单定价页顶部按「昨日销量×1.1（无数据按8份）」推算在售菜品原料缺口，可一键购入全部缺口或按行买缺口（按各食材起订量取整）。
- **库存速览过滤**：经营总览库存表顶部「只看在售菜品所需原料」开关。
- **按批次独立计算保质期**：每次采购/到货都是独立批次（记录购入日、独立过期日），互不牵连——三天前买的草鱼明天到期，不会把今天新买的也一起算过期；烹饪按 FIFO 优先消耗临期批次。库存速览新增「批次明细」列，逐批显示 `数量·第N天购入·剩X天`。
- **过期食材处置**：每天开局都会检查过期食材（无金额门槛、无冷却）：任何过期批次自动暂存冷柜并出现“食材过期提醒”事件；若不处理，次日过期会累积进同一事件（不会重复弹多个）。事件明细按批次标注「第N天购入，第M天晨检发现过期」。玩家可选「低价卖给大学生（按市价40%回收现金、口碑-5、账面损耗单独入账）/加强管理/直接扔掉」；事件逾期未处理默认按扔掉入账。
- **身世专属剧情事件**：凄惨→中国大孝子记者采访（如实相告/装老实人/隐瞒，各有正反分支，含“不抱怨排队”舆论期与“泥泞中开出鲜花”五星长评或“死装”一星）；普通→“原来你也玩原神”（玩=现金+5000口碑-5 / 不玩=口碑+5）；优渥→催婚（相亲→结婚后每日家庭支出+500且口碑每天+0.1 / 出柜→后续偶现“死gay”“爱只是爱”评价 / 拒绝无事），已婚可刷离婚（修复或现金五五分割），离异后可再婚；豪门→“当年把你丢掉是个错误”假父母（给钱自定金额，给足必成交、给少按概率被嫌、可否认口碑-2、亲子鉴定确认为假口碑+5）。
- **事件历史中文化**：事件与处理选项在待办面板与历史表中均显示中文名（引擎仍存内部 id）。
- 剧情舆论/婚姻状态存于 `state.story`，旧存档读取时自动补默认字段（无需重开）。

## 平衡调整

所有可调数值集中在 `src/game/config.ts`（客流系数、效用参数、产能参数、口碑速率、工资曲线、事件概率、博主/采访规则、困难度系数、性格/身世效果表），不散落在组件中。
